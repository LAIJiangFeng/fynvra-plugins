# 飞书群反馈值班

Fynvra 官方插件。把飞书机器人拉进公司内部群，或者让同事直接私聊它，大家就能反馈问题。Fynvra 在电脑上自动处理这些反馈：

- **分诊**：每条反馈交给只读的分诊会话，判断是 bug、新功能、提问还是无效内容，然后引用原消息回复。
- **追问**：信息不够时会追问，最多 2 轮。追问后 24 小时没人回复，就记为「未确认」。
- **修复 bug**：只有分诊定位到原因的 bug，才会交给受限的值班会话修复。值班会话派出任务，检查通过后开 PR（不会合并），PR 开出后在原消息下回复链接，会附上简短的改动和解决内容。
- **新功能**：分诊按「值不值得做、合不合理、符不符合设计」三个问题评估。通过的需求进入设置页「待确认需求」，**你采纳后**才会开始做；如果拒绝，会回复「暂不采纳」。
- **兜底**：值班会话空闲 30 分钟还没有 PR，或者任务失败，会标为「需要维护者处理」并通知你。

功能和 Telegram 插件（`com.fynvra.telegram` 0.1.6）一样，只是收发消息改走飞书。

## 先建一个专用的企业自建应用

**建议新建一个专用的企业自建应用**，只开下面列出的权限，不要复用权限很大的现有应用。原因有三点：

1. App Secret 保存在这台电脑上。应用权限越小，Secret 万一泄露，损失也越小。
2. 如果同一个应用还有别的程序也建了长连接，飞书只会把每条事件推给其中一个连接，消息会被分走。
3. 把事件订阅方式改成长连接以后，这个应用原来配置的回调地址就不再生效。

### 权限

在飞书开放平台「权限管理」里开通：

| 权限 | 用途 |
| --- | --- |
| `im:message` | 读消息、下载消息里的图片和文件 |
| `im:message:send_as_bot` | 以机器人身份回复 |
| `im:message.group_at_msg:readonly` | 接收群里 @机器人 的消息 |
| `im:message.group_msg` | 获取群组中所有消息（敏感权限，需要管理员审批） |
| `im:message.p2p_msg:readonly` | 接收私聊消息 |
| `im:resource` | 下载消息里的图片和文件 |
| `im:chat:readonly` | 读取群名，用来在设置页显示（可以不开） |

不开 `im:message.group_msg` 也能用，只是机器人只能收到 @ 它的群消息：「先发图再 @」「@ 前后的文字一起读」这类用法不生效。直接回复机器人的消息也需要这个权限。

读取群里被引用的消息（「获取指定消息的内容」接口）同样需要「获取群组中所有消息」权限。没开的话，群里的引用读不到，机器人会告诉 AI「引用的消息没能读取（缺少读取群消息的权限）」，并在回复里说明。群设置里关闭了「新成员可查看历史消息」时，机器人入群前的消息也读不到。

另外要在「应用能力」里开启**机器人**。

### 事件

在「事件与回调 → 事件配置」里添加：

- `im.message.receive_v1`：接收消息
- `im.message.recalled_v1`：消息被撤回。投递前撤回的消息不再投递
- `im.chat.member.bot.added_v1`：机器人进群，群会出现在「候选会话」
- `im.chat.member.bot.deleted_v1`：机器人被移出群，标记为「已移出」
- `im.chat.access_event.bot_p2p_chat_entered_v1`：用户打开和机器人的私聊（可选）。不订阅也没关系，私聊会在对方第一次发消息时出现在候选会话

## 操作顺序

1. 在 Fynvra 打开「设置 → 插件 → 市场」，安装「飞书群反馈值班」，在插件卡片上启用。
2. 在飞书开放平台创建企业自建应用，开启机器人，开通上面的权限。
3. 打开插件的「设置」，在「连接」里填 App ID 和 App Secret，点「保存」。插件会先连上飞书。
4. 回到飞书开放平台，在「事件与回调」里把订阅方式改成「**使用长连接接收事件**」并保存，再添加上面的事件。飞书要求保存长连接方式时，已经有客户端连上，所以要先做第 3 步。
5. 创建版本并发布。权限和事件都要发布后才生效。
6. 把机器人拉进群，或者私聊它。会话出现在「候选会话」后，选一个 git 工作区（要有默认分支和远端 `origin`），点「允许」。
7. 本机需要先运行 `gh auth login`，值班会话才能开 PR。

长连接不需要公网地址，也不需要配置回调 URL。

## 怎么发反馈

**群聊**（已允许的群）：

- **@机器人**：在消息里 @ 机器人，文字、图片一起处理。富文本消息里的 @、文字、链接和图片都会识别。
- **回复机器人**：直接回复机器人发的消息，不用 @。
- **先发图再 @**：同一个人 60 秒内发的图片和文件，会并入他接着发的 @ 消息或回复。
- **先 @ 再发图**：@ 里有文字、没有图时，机器人等 8 秒，这期间同一个人发的图会并入同一条反馈。反馈投递后 60 秒内再发的图，会作为这条反馈的补充处理（计入限流）。
- **只 @ 不写内容**：用这个人 60 秒内发的消息或引用的消息；都没有的话，等他的下一条消息（60 秒内）；还没有，就让 AI 追问。
- 3 秒内连续 @ 的几条合成一条。

**私聊**（已允许的私聊）：

- 每条消息都算反馈，不需要 @。
- 同一个人连续发的消息合成一条：有附件时等 3 秒，只有文字时等 8 秒，期间再发的都并进去，从第一条算起最多等 30 秒。
- 机器人正在追问时，直接回答就行，不用引用回复。

没被允许的群和私聊，机器人一律不回复、不处理，只会出现在「候选会话」里。

## 像人一样读消息

用户发了什么、引用了什么，机器人就读什么：

- **引用回复**：引用一条消息再 @机器人（或回复机器人、在私聊里引用），机器人会读被引用的那条：文字最多 2000 字，图片和文件按普通附件处理，和本条的附件一起计入每条 10 张图、10 个文件的上限。只引用、只 @、自己没写字也会照常处理。引用的消息读不到时（已删除、机器人看不到、缺少权限），照常处理并说明原因。
- **话题**：在话题里 @机器人时，会读话题的第一条消息（只读文字，最多 500 字）。
- **合并转发**：自己发的、@ 前发的、被引用的合并转发都会读成聊天记录（最多 30 条、4000 字）。作者只写匿名标签，里面的图片和文件只写占位，不下载。
- **@ 前后的文字**：同一个人 @ 前 1 分钟内发的消息（文字合计最多 2000 字，超出丢最早的），以及 @ 后机器人还在等的时候（3 秒或 8 秒，从 @ 算起最多 30 秒）接着发的文字，都会和这条 @ 一起读。已经开始处理后再发的文字不自动补充，可以引用机器人的回复或再 @ 一次。
- **撤回**：消息在投递给分诊之前撤回，就不会投递；一条反馈里的消息都撤回了，整条反馈丢弃。已经开始处理的不受影响。
- **引用别人的反馈**：引用某条已经处理过的反馈再 @机器人，会作为新反馈处理，并关联到那张卡片作背景。
- **连续对话**：机器人在群里回复了某个成员后，接下来几分钟内（默认 5 分钟），这个成员不 @、不回复直接发的消息也会读，当作对刚才那条回复的继续。只跟随和机器人说过话的那个人，其他成员不跟随；@ 了别人（含 @所有人）或引用了别人消息的不跟随。机器人判断不是对它说的话不会回复，也不计入限流；是对它说的就照常回复，并重新计时。时长可以在设置页「限流」里调整，填 0 关闭。私聊不受影响（私聊里每条本来就算反馈）。

已知行为：

- 别人没被引用的消息不读，因为他们没有找机器人。
- 编辑后的消息机器人看不到：飞书不会把「消息被编辑」推给机器人，机器人读到的是编辑前的内容。

## 一个会话绑定多个项目

和 Telegram 插件的群一样：在「已允许的会话」里，可以给一个会话添加多个项目，第一个是主项目。每个项目可以写一句说明（最多 200 字）。反馈先交给主项目分诊；分诊判断属于其他项目时，会把同一条反馈（正文和附件）原样转给那个项目处理，每条最多转一次。追问和补充附件会投给卡片所属的项目。需要支持该功能的 Fynvra。

## 维护者

机器人不知道谁是维护者：凭说话内容判断不了，昵称谁都能改。没绑定时，你在群里提的需求也会被回复「由维护者决定」。绑定后，插件按发送者的 open_id 识别你；open_id 由飞书服务器填写，别人伪造不了。只能绑定一个人。

- **绑定**：在设置页「维护者」里点「绑定」，再点「打开机器人私聊」，用要绑定的飞书账号把码发给机器人（前面加不加「绑定」都可以，如 `绑定<码>`、`/bind <码>` 或只发码）。码 10 分钟内有效，只能用一次，点「重新生成」会作废旧码；发「绑定 <码>」但码无效或过期时，机器人会提示你重新生成。这个私聊不用先允许。绑定成功后机器人会回复你，电脑上也会收到通知。
- **解除**：在设置页「维护者」里点「解除绑定」。
- **绑定后的变化**：
  - 你提的需求清楚、评估也通过时，直接开始做，做好后把 PR 发到群里。
  - 评估有顾虑时，机器人先说明顾虑；你回复「确认」就开始做，回复「算了」就不做。
  - 别人提的需求（待确认或评估未通过），引用机器人给它的回复说「确认」就能采纳，说「算了」就不做。
  - 没有引用时，「@机器人 确认」作用于这个会话最近 24 小时内更新过的待确认需求。在连续对话里和私聊里也可以直接说。
  - 设置页的「采纳 / 拒绝」照旧可用。普通成员说「确认」不会采纳任何东西。
- **确认词**：确认、确定、开始、开始吧、做、做吧、可以、可以做、行、好、好的、采纳、同意、ok、yes、y、go。
- **取消词**：算了、不做、不做了、取消、不要、不用了、不采纳、不同意、no、n。
- 整句话要正好是其中一个词（末尾的标点和大小写不影响）。确认和取消不计入限流，你提的其他消息照常计入。
- 群里的回复所有人都能看到。保密规则和出站过滤不会因为维护者身份而放宽。

## 设置页

- **连接**：状态和机器人名称。下面依次是 App ID 一行；App Secret 一行，右侧是「保存」和「清除」（清除前要确认）；最后一行是提示「需要的权限和事件见使用说明」。App Secret 不会回显，只显示首尾两位。如果只改 App ID，App Secret 可以留空。
- **维护者**：未绑定时是「绑定」按钮；有码时显示码、「打开机器人私聊」和「重新生成」；已绑定时显示维护者（匹名标签）和「解除绑定」，见「维护者」一节。
- **会话**：「候选会话」和「已允许的会话」，用「群聊」「私聊」徽标区分。已允许的会话每个一个列表：第一行是会话本身（群聊显示在群里或已移出、项目数、移除会话），然后是各项目（说明、设为主项目、移除），最后一行是「添加项目」。
- **模型**：分诊模型、分诊思考档位、值班模型、值班思考档位，用法和 Telegram 插件相同。
- **限流**：每人每小时最多处理几条（1–1000，默认 5）。超出后，同一个窗口里只提示一次。同一组里的「连续对话（分钟）」是 0–60 的整数，默认 5，0 表示关闭。
- **待确认需求**：新功能的三问评估，可以「采纳」或「拒绝」。
- **反馈记录**：最近 50 条反馈的状态，有 PR 时可以直接打开。

启用和停用在 Fynvra 的插件卡片上操作。

## 隐私与安全

- 插件不调用通讯录接口，不读取成员姓名。交给 AI 的发送者是根据 open_id 生成的匿名短标签，例如「成员 3f2a」。消息里 @ 别人的地方，会显示成「@名字」（这个名字来自消息本身）。
- 开了「获取群组中所有消息」后，机器人能收到群里的所有消息。插件只在内存里暂存每个人最近 60 秒的消息（每人最多 10 条，每群最多 200 人），只用来拼接他自己的 @ 或回复：只有他自己 @ 机器人或回复机器人时，才和那条消息一起交给 AI。连续对话期间，会读这个成员自己发的消息。这些消息不写盘、不写日志，过期就丢，也不会混用不同人的消息。其他成员的消息只有被引用时才会读。
- 消息都作为不可信内容交给分诊会话，伪造的标签会被转义。分诊会话只读，值班会话按固定规则受限，两者都运行在工作区的干净检出里，不会动你正在改的代码。
- **飞书里只会出现过滤后的分诊回复和固定模板**。每条回复都先经过 Fynvra 的出站过滤：本机路径、用户名、主机名会被替换。疑似含密钥时，整条回复不发，改发中性提示，并通知你。回复里的 `<at>` 标签会被转成普通文字，机器人不会 @ 人或 @所有人。值班会话的输出不会发到飞书。
- 只有完全匹配 `https://github.com/<owner>/<repo>/pull/<数字>` 的 PR 链接会发出去，其他情况只说「已提交修复 PR」。
- PR 说明里只写问题标题和来源，来源是「飞书群反馈（卡片 #N）」或「飞书私聊反馈（卡片 #N）」。不写会话名、成员、链接和凭证。
- App Secret 保存在 Fynvra 的插件密钥里，不写进插件数据。Fynvra 的日志和出站过滤会抹掉它。飞书 SDK 的日志只保留状态码和错误码，不含请求体和请求头。

## 网络与代理

- 只连接飞书 `open.feishu.cn`（国际版 Lark 暂不支持）。
- 插件进程本身没有代理环境变量。连接时会读取 Fynvra 的代理设置（「设置 → 通用 → 网络代理」），HTTP 接口和长连接都走这个代理；改了代理后，重新保存一次凭证或重启插件才会生效。
- 如果 Fynvra 内置的 Node 版本不支持按代理建连接（低于 22.21 或 24.5），插件会直连飞书。飞书是国内服务，一般可以直连。
- 如果 TLS 校验被关闭（`NODE_TLS_REJECT_UNAUTHORIZED=0`），插件会拒绝连接。

## 附件

- 支持图片和文件，格式和上限与 Fynvra 输入框相同。下载上限是图片 20 MB、文件 32 MB，超过上限会在下载时中止。每条反馈最多 10 张图、10 个文件。
- 语音、视频、表情包、卡片消息、群名片等类型不处理（合并转发见「像人一样读消息」）。没处理的附件会在同一条回复里说明。
- 附件临时存在插件数据目录的 `attachments/` 里。这条反馈分诊结束后就删除（转交的反馈在目标项目分诊结束后删除），丢弃的反馈也会删除；残留文件在 24 小时后启动时清理。

## 常见问题

- **收不到消息**：检查订阅方式是否改成了「使用长连接接收事件」，`im.message.receive_v1` 有没有添加，版本有没有发布。再检查这个应用是否还有别的程序在连长连接，有的话消息会被分走。
- **状态显示「应用还没发布，或没开启机器人能力」**：在开放平台开启机器人能力，然后创建版本并发布，等管理员审核通过。
- **权限加了但不生效**：权限变更要重新创建版本并发布后才生效。`im:message.group_msg` 还需要管理员审批。
- **状态显示「App ID 或 App Secret 不对」**：到「凭证与基础信息」重新复制。如果重置过 App Secret，也要在这里重新填写。
- **群名显示成「群聊 · xxxxxx」**：没开 `im:chat:readonly`，或者开了但还没发布，不影响使用。
- **Fynvra 关着的时候**：这期间不会处理消息。长连接断开时，飞书不会补推这段时间的消息。

## 开发

源码在 `src/`（TypeScript），`dist/` 是提交到仓库的编译产物（ESM、未压缩、保留注释），`host.main` 指向 `dist/index.js`。运行时依赖只有官方 SDK `@larksuiteoapi/node-sdk`（版本固定为确切版本号，lockfile 一起提交）。SDK 不含原生 `.node` 模块，安装后约 40 MB。

安装依赖并编译（借用 Fynvra 仓库自带的 TypeScript 和 `@types/node`，在注册表仓库根目录执行）：

```bash
npm install --ignore-scripts --prefix official/com.fynvra.feishu
node ../fynvra/node_modules/typescript/bin/tsc -p official/com.fynvra.feishu --typeRoots ../fynvra/node_modules/@types
```

改完源码后要重新编译，并把 `dist/` 一起提交。`node_modules/` 不要提交。

本地联调：先在插件目录执行 `npm install --ignore-scripts`，再用开发版 Fynvra 打开「设置 → 插件 → 添加本地 Fynvra 插件（开发）」，选择 `official/com.fynvra.feishu` 目录。本地添加和「从源目录重新复制」会把 `node_modules/` 一起复制过去。市场构建会按 lockfile 用 `npm ci --omit=dev --ignore-scripts` 安装依赖再打包。
