# Telegram 群反馈值班

Fynvra 官方插件。把一个 Telegram 机器人拉进你的用户群，群成员 @ 机器人就能反馈问题，Fynvra 在电脑上自动处理：

- **分诊**：每条反馈交给只读的分诊会话判断是 bug、新功能、提问还是无效内容，并在群里回复。
- **追问**：信息不够时追问，最多 2 轮；追问后 24 小时没人回复就结束，记为「未确认」。
- **修复 bug**：只有分诊定位到原因的 bug 才会交给受限的值班会话修复，派出任务、检查通过后开 PR（不合并），PR 开出后在群里回复链接。
- **新功能**：分诊按「值不值得做、合不合理、符不符合设计」三问评估，通过的进入设置页「待确认需求」，**由你采纳后**才会动手；拒绝时群里回复「暂不采纳」。
- **兜底**：值班会话空闲 30 分钟仍没有 PR、或任务失败时，标为「需要维护者处理」并通知你。

## 安装与配置

1. 在 Fynvra 打开「设置 → 插件 → 市场」，安装「Telegram 群反馈值班」，在插件卡片上启用。
2. 在 Telegram 找 [@BotFather](https://t.me/BotFather)，发送 `/newbot` 创建机器人，拿到 Bot Token。
3. 打开插件的「设置」，把 token 填进「Bot Token」。状态显示「已连接」即可。
4. 把机器人拉进群，在群里 @ 它发一条消息。这个群会出现在「候选群」里。
5. 给候选群选一个 git 工作区（要有默认分支和远端 `origin`），点「允许」。之后群里 @ 机器人、回复机器人的消息或者用 `/bug` 命令，都算反馈。
6. 本机需要先运行 `gh auth login`，值班会话才能开 PR。

如果 @ 了机器人没有反应：在 @BotFather 用 `/setprivacy` 关闭隐私模式，再把机器人移出群、重新拉进来。

## 怎么发反馈

- **配文里 @**：图片或文档的配文里 @机器人，图和文字一起处理。
- **回复机器人**：直接回复机器人的消息，不用 @。
- **先发图再 @**：同一个人 60 秒内发的图片、文件（含相册的每一张）会并入他接着发的 @ 或回复。
- **先 @ 再发图**：@ 里有文字、没有图时，机器人等 8 秒，这期间同一个人发的图并入同一条；已经投递后 60 秒内再发的图，按「回复了这条反馈」作为补充处理（计入限流）。
- **只 @ 不写内容**：先取这个人 60 秒内的前一条文字；没有就等他的后一条消息（60 秒内），还没有就让 AI 追问。

「先发图再 @」「先 @ 再发图」「只 @ 不写内容」需要机器人能看到群里的普通消息。机器人默认开着隐私模式，只收得到命令、@它和回复它的消息，请二选一：

- 在 @BotFather 里 `/setprivacy` → 选择机器人 → `Disable`，然后**把机器人移出群再重新拉进来**，修改才对已有的群生效；
- 把机器人设为群管理员。

「配文里 @」和「回复机器人」在隐私模式下也能用。设置页的「连接」区会显示「隐私模式：开启 / 关闭」。

## 设置页

- **连接**：连接状态（已连接 / 网络错误 / token 无效 / 另有实例在轮询 / 未配置）、隐私模式开关、Bot Token、清除 token。
- **候选群 / 已允许的群**：允许时选择绑定的工作区；移除前需要确认。
- **限流**：每人每小时最多处理几条（1–1000，默认 5），超出后同一个窗口里只提示一次「你发得有点快」。
- **待确认需求**：新功能的三问评估，采纳或拒绝。
- **最近记录**：最近 50 条反馈的状态，有 PR 时可以直接打开。
- **使用说明**：按隐私模式是否开启给出对应的提示。

启用和停用在 Fynvra 的插件卡片上操作。

## 隐私与安全

- 机器人只处理 @机器人、`/bug` 和回复机器人的消息。隐私模式关闭时机器人能看到群里所有消息，但插件只在内存里暂存每个人最近 60 秒的消息（每人最多 10 条，每群最多 200 人），只用来拼接他自己的 @ 或回复；不写盘、不写日志、不下载附件、不交给 AI，过期即丢，不同的人之间绝不混用。被并入的消息在投递正文里标明是 @ 前还是 @ 后发的。私聊和频道一律忽略。
- 只处理你允许过的群；其他群只记为候选，消息不处理。
- 群消息都作为不可信内容交给分诊会话，伪造的标签会被转义。分诊会话只读，值班会话按固定规则受限，都运行在工作区的干净检出里，不动你正在改的代码。
- **群里只会出现过滤后的分诊回复和固定模板**。每条回复都先经过 Fynvra 的出站过滤：本机路径、用户名、主机名会被替换；疑似含密钥时整条不发，改发中性提示，并通知你。值班会话的输出不会发到群里。
- 群里只发完全匹配 `https://github.com/<owner>/<repo>/pull/<数字>` 的 PR 链接，其余只说「已提交修复 PR」。
- PR 说明里只写问题标题和来源（「Telegram 群反馈（卡片 #N）」），不写群名，也不写分诊摘要。
- Bot Token 保存在 Fynvra 的插件密钥里，不写进插件数据；Fynvra 的日志和出站过滤会抹掉它，设置页只显示首尾几位。
- 网络请求只发往 `api.telegram.org`，走 Fynvra 的代理设置；TLS 校验被关闭（`NODE_TLS_REJECT_UNAUTHORIZED=0`）时拒绝连接；配置了代理但 Node 版本不支持 `proxyEnv` 时拒绝直连。

## 限制

- Fynvra 关着的时候不会处理群消息（重启后从上次的位置继续）。
- 同一个 token 只能有一处在轮询，否则显示「另有实例在轮询」。
- 支持图片和文档（与 Fynvra 输入框相同的格式和上限）：图片 PNG / JPEG / GIF / WebP，文档为文本（UTF-8 / GBK / UTF-16）、PDF、Word `.docx`、Excel `.xlsx`；每条最多 10 张图（单张 ≤ 20 MB）、10 个文件，文字合计 ≤ 20 万字符。配文里 @机器人、用 /bug 或回复机器人都算反馈，相册与 3 秒内连发的多条合并成一条。Telegram 只允许机器人下载 20 MB 以内的文件；视频、语音、贴纸、动图不处理。没处理的附件会在同一条回复里说明。附件临时存在插件数据目录的 `attachments/`，投递后删除，残留文件 24 小时后清理。
- 从内置版升级：第一次启动时自动导入旧的 `telegram.json`（token 转存到插件密钥），之后旧文件由 Fynvra 改名留底。旧的分诊 / 值班会话不归本插件所有，首次用到时会重建。

## 开发

源码在 `src/`（TypeScript），`dist/` 是提交到仓库的编译产物（ESM、未压缩、保留注释），`host.main` 指向 `dist/index.js`。运行时只用 Node 内置模块，没有 npm 依赖。

重新编译（借用 Fynvra 仓库自带的 TypeScript 与 `@types/node`，在注册表仓库根目录执行）：

```bash
node ../fynvra/node_modules/typescript/bin/tsc -p official/com.fynvra.telegram --typeRoots ../fynvra/node_modules/@types
```

改完源码要重新编译并一起提交 `dist/`；编译后 `git status` 应当没有 `dist/` 的额外改动。

测试（node:test，针对 `dist/`，用假的宿主 API）：

```bash
node --test official/com.fynvra.telegram/test
```

本地联调：用开发版 Fynvra 打开「设置 → 插件 → 添加本地 Fynvra 插件（开发）」，选择 `official/com.fynvra.telegram` 目录。
