# Telegram 群反馈值班

Fynvra 官方插件。把一个 Telegram 机器人拉进你的用户群，群成员 @ 机器人就能反馈问题，Fynvra 在电脑上自动处理：

- **分诊**：每条反馈交给只读的分诊会话判断是 bug、新功能、提问还是无效内容，并在群里回复。
- **追问**：信息不够时追问，最多 2 轮；追问后 24 小时没人回复就结束，记为「未确认」。
- **修复 bug**：只有分诊定位到原因的 bug 才会交给受限的值班会话修复，派出任务、检查通过后开 PR（不合并），PR 开出后在群里回复链接，并附上简短的改动和解决内容。
- **新功能**：分诊按「值不值得做、合不合理、符不符合设计」三问评估，通过的进入设置页「待确认需求」，**由你采纳后**才会动手；拒绝时群里回复「暂不采纳」。
- **兜底**：值班会话空闲 30 分钟仍没有 PR、或任务失败时，标为「需要维护者处理」并通知你。

## 安装与配置

1. 在 Fynvra 打开「设置 → 插件 → 市场」，安装「Telegram 群反馈值班」，在插件卡片上启用。
2. 在 Telegram 找 [@BotFather](https://t.me/BotFather)，发送 `/newbot` 创建机器人，拿到 Bot Token。
3. 打开插件的「设置」，把 token 填进「Bot Token」，点「保存」。状态显示「已连接」即可。
4. 把机器人拉进群，在群里 @ 它发一条消息。这个群会出现在「候选群」里。
5. 给候选群选一个 git 工作区（要有默认分支和远端 `origin`），点「允许」。之后群里 @ 机器人、回复机器人的消息或者用 `/bug` 命令，都算反馈。
6. 本机需要先运行 `gh auth login`，值班会话才能开 PR。

如果 @ 了机器人没有反应：在 @BotFather 用 `/setprivacy` 关闭隐私模式，再把机器人移出群、重新拉进来。

## 一个群绑定多个项目

一个用户群里的反馈可能分属不同的仓库（例如前台和后台）。群允许之后，可以在设置页「已允许的群」里给它绑定多个项目：

- **配置**：在群列表最后一行「添加项目」的下拉框里选一个还没绑定的 git 工作区，点「添加」。每个项目可以写一句「说明」（这个项目管什么，最多 200 字，可不填），离开输入框即保存。列表里第一个是「主项目」，可以用「设为主项目」调整；只剩一个项目时不能移除。
- **AI 怎么转交**：群消息先交给主项目的分诊，投递时附上本群其他项目的名称和说明。分诊判断反馈属于其中某个项目时，插件不发这一次的回复，把同一条反馈（正文和附件）原样转给那个项目的分诊；之后的定位、追问、修复都在那个项目里做，PR 开到那个仓库。群成员回复机器人或补发附件时，投给这张卡片所属项目的分诊。两个项目同名时，名称后面加工作区 id 区分。
- **最多转一次**：转过去的分诊如果还想再转，插件忽略，照常在这个项目里处理。转交不另计限流。
- **互相看不到代码**：每个「群 × 项目」有自己的只读分诊会话（用到时再创建），只读自己项目的干净检出；主项目的分诊只知道其他项目的名称和说明。
- 自动转交需要支持该功能的 Fynvra（`triage_report` 带 `project` 字段）。旧版 Fynvra 不会转交，主项目照常处理全部反馈。
- 从 0.1.3 升级时，原来的绑定自动变成只有一个主项目的列表，行为不变。

## 怎么发反馈

- **配文里 @**：图片或文档的配文里 @机器人，图和文字一起处理。
- **回复机器人**：直接回复机器人的消息，不用 @。
- **先发图再 @**：同一个人 60 秒内发的图片、文件（含相册的每一张）会并入他接着发的 @ 或回复。
- **先 @ 再发图**：@ 里有文字、没有图时，机器人等 8 秒，这期间同一个人发的图并入同一条；已经投递后 60 秒内再发的图，按「回复了这条反馈」作为补充处理（计入限流）。
- **只 @ 不写内容**：用这个人 @ 前 60 秒内发的文字当正文；引用了一条消息的直接投递；前后都没有内容才等他的后一条消息（60 秒内），还没有就让 AI 追问。

「先发图再 @」「先 @ 再发图」「只 @ 不写内容」需要机器人能看到群里的普通消息。机器人默认开着隐私模式，只收得到命令、@它和回复它的消息，请二选一：

- 在 @BotFather 里 `/setprivacy` → 选择机器人 → `Disable`，然后**把机器人移出群再重新拉进来**，修改才对已有的群生效；
- 把机器人设为群管理员。

「配文里 @」和「回复机器人」在隐私模式下也能用。设置页的「连接」区会显示「隐私模式：开启 / 关闭」。

## 像人一样读消息

- **引用回复**：@机器人、`/bug` 或回复机器人时引用了一条消息，机器人会一起读被引用的消息：文字（最多 2000 字）、图片和文件（和自己发的附件共用每条 10 张图、10 个文件的上限），以及部分引用的片段。只引用、自己没写字也算反馈。语音、视频、贴纸等列为未处理。转发来的消息只标「转发的消息」，不写原作者；引用其他会话的消息只读引用的片段和媒体。
- **@ 前后的文字**：同一个人 @ 前 1 分钟内发的文字（合计最多 2000 字，超出时保留最近的）和 @ 后等待期间（3 或 8 秒，连续发时最多 30 秒）发的文字会一起读。已经开始处理后再发的文字不自动补充，请引用机器人的回复或再 @ 一次。
- **引用别人的反馈再 @**：作为新反馈处理，并关联到那条反馈的卡片作背景。
- **连续对话**：机器人在群里回复某个成员后，默认 5 分钟内这个成员不 @、不回复机器人发的消息也会读，接着刚才那条反馈处理；机器人每回复一次就重新计时。只跟随和机器人说过话的那个人；@别人或引用别人的消息不跟随；不是对机器人说的不会回复（也不占限流次数）。跟随的消息计入限流，超出时不提示。可以在设置页「限流」里调整分钟数（0–60），填 0 关闭。
- **话题群**：消息在论坛话题里时，会带上话题名。
- **别人没被引用的消息不读**：机器人只读 @ 它的人自己发的消息和被引用的消息。
- **编辑消息**：编辑消息补上 @ 会被处理；已经交给机器人的消息再编辑，机器人看不到。私聊仍然不支持。
- 交给 Fynvra 的正文超过 64 KiB 时，依次截短引用文字和 @ 前的消息，并标注「（过长，已截断）」。

「@ 前后的文字」和「连续对话」同样需要关闭隐私模式或把机器人设为管理员；引用回复在隐私模式下也能用。

## 维护者

机器人本来不知道谁是维护者，也不能凭昵称判断（昵称谁都能改），所以你在群里提的需求也会被回「由维护者决定」。把你的 Telegram 账号绑定为维护者后，机器人按 Telegram 用户 id 认你（由 Telegram 服务器填写，伪造不了）。只能绑定一个人。

- **绑定**：设置页「维护者」区点「绑定」，再点「在 Telegram 中绑定」（用要绑定的 Telegram 账号打开），在 Telegram 里点「开始」。链接 10 分钟内有效，只能用一次，点「重新生成」后旧链接作废；链接失效时机器人会提示「绑定链接已失效，请在 Fynvra 里重新生成。」。绑定成功后私聊里会收到确认，电脑上也有通知。
- **解除**：设置页「解除绑定」（需要确认）。
- **绑定后**：你在群里提的新功能，需求清楚、三项评估都通过就直接开始做，做好后把 PR 发到群里；有顾虑时机器人先说明，回复「确认」就开始做，回复「算了」就不做；需求不清楚时照常追问。别人提的需求（待确认或评估未通过），引用机器人给它的回复说「确认」就能采纳。设置页的「采纳 / 拒绝」照旧可用。
- **一句话确认或取消**：引用回复机器人、在连续对话里或 @ 机器人时，整句话（去掉末尾标点、不区分大小写）就是下面的词才算。作用于所回复的那条需求；没有指明时作用于这个群最近 24 小时内最新的待确认需求。只对新功能生效，不计限流。
  - 确认：确认、确定、开始、开始吧、做、做吧、可以、可以做、行、好、好的、采纳、同意、ok、yes、y、go
  - 取消：算了、不做、不做了、取消、不要、不用了、不采纳、不同意、no、n
- 群里的回复所有人都能看到，保密规则和出站过滤不因为维护者身份而放宽；维护者的消息也计入限流（只有确认词和取消词不计）。普通成员说「确认」不会采纳任何东西。

## 设置页

- **连接**：状态、机器人、隐私模式；隐私模式开着时提示怎么关。「Bot Token」一行里填写并「保存」，说明里显示已设置的掩码，已设置时可以「清除」。
- **维护者**：未绑定时「绑定」（生成链接后可「重新生成」），已绑定时显示维护者和「解除绑定」，见上一节。
- **群**：「候选群」列出 @ 过机器人的群和出现时间，选项目后「允许」；「已允许的群」每个群一个列表：第一行是群本身（在群里 / 已移出、项目数、移除群），接着是各项目（说明、设为主项目、移除），最后是「添加项目」。移除前需要确认。
- **模型**：分诊模型、分诊思考档位、值班模型、值班思考档位，见下一节。
- **限流**：每人每小时最多处理几条（1–1000，默认 5），超出后同一个窗口里只提示一次「你发得有点快」；连续对话（分钟，0–60，默认 5，0 关闭）。
- **待确认需求**：新功能的三问评估，「采纳」或「拒绝」。
- **反馈记录**：最近 50 条反馈的状态，有 PR 时可以直接打开。

启用和停用在 Fynvra 的插件卡片上操作。

## 模型

设置页「模型」区可以分别给分诊和值班选模型，例如分诊用便宜快速的、修复用强的：

- **分诊模型**：读群消息、追问、回复。默认跟随 Fynvra 的默认模型。
- **值班模型**：修复 bug 并开 PR，值班派出的修复任务也跟随它。默认跟随 Orchestrator 角色的模型。
- 下拉里列出 Fynvra 里启用并且配了 key 的模型（「服务名 / 模型名」），第一项「默认（跟随 Fynvra）」。选择改了立即保存，并应用到已有的分诊会话（每个「群 × 项目」一个）或值班会话（每个工作区一个），不重建会话、不丢分诊上下文。正在运行的会话在下一次投递前补上（插件重启会丢掉这个待应用记录，再选一次即可）。
- 所选模型被删除或停用时，下拉里标「（不可用）」，新会话改用默认模型（设置页提示「所选模型不可用，新会话用默认」）；带所选模型建会话或换模型失败时记一条日志，设置页提示「所选模型不可用，已改用默认」。
- **思考档位**：选了模型后，下面出现「分诊思考档位」或「值班思考档位」：第一项「默认」，其余是这个模型支持的档位，模型自己的默认档位标「（默认）」。模型选「默认」或不支持思考时不显示。改档位和改模型一样立即保存并应用到已有会话；换成不支持原档位的模型时，档位回到「默认」。带档位建会话失败时，模型和档位一起改用默认。需要支持该功能的 Fynvra，旧版不显示档位。
- 需要支持该功能的 Fynvra。旧版 Fynvra 显示「当前 Fynvra 不支持选模型」，其他功能照常。

## 隐私与安全

- 机器人只处理 @机器人、`/bug` 和回复机器人的消息。隐私模式关闭时机器人能看到群里所有消息，但插件只在内存里暂存每个人最近 60 秒的消息（每人最多 10 条，每群最多 200 人），只用来拼接他自己的 @ 或回复；不写盘、不写日志、不下载附件、不交给 AI，过期即丢，不同的人之间绝不混用。连续对话期间，会读这个成员自己发的消息。被并入的消息在投递正文里标明是 @ 前还是 @ 后发的。私聊只认维护者绑定链接（失效的链接会提示重新生成），其余私聊和频道一律忽略、不回复。
- 只处理你允许过的群；其他群只记为候选，消息不处理。
- 群消息都作为不可信内容交给分诊会话，伪造的标签会被转义。分诊会话只读，值班会话按固定规则受限，都运行在工作区的干净检出里，不动你正在改的代码。
- **群里只会出现过滤后的分诊回复和固定模板**。每条回复都先经过 Fynvra 的出站过滤：本机路径、用户名、主机名会被替换；疑似含密钥时整条不发，改发中性提示，并通知你。值班会话的输出不会发到群里。
- 群里只发完全匹配 `https://github.com/<owner>/<repo>/pull/<数字>` 的 PR 链接，其余只说「已提交修复 PR」。
- PR 说明里只写问题标题和来源（「Telegram 群反馈（卡片 #N）」），不写群名，也不写分诊摘要。
- Bot Token 保存在 Fynvra 的插件密钥里，不写进插件数据；Fynvra 的日志和出站过滤会抹掉它，设置页只显示首尾几位。
- 网络请求只发往 `api.telegram.org`，走 Fynvra 的代理设置；TLS 校验被关闭（`NODE_TLS_REJECT_UNAUTHORIZED=0`）时拒绝连接；配置了代理但 Node 版本不支持 `proxyEnv` 时拒绝直连。

## 限制

- Fynvra 关着的时候不会处理群消息（重启后从上次的位置继续）。
- 同一个 token 只能有一处在轮询，否则显示「另有实例在轮询」。
- 支持图片和文档（与 Fynvra 输入框相同的格式和上限）：图片 PNG / JPEG / GIF / WebP，文档为文本（UTF-8 / GBK / UTF-16）、PDF、Word `.docx`、Excel `.xlsx`；每条最多 10 张图（单张 ≤ 20 MB）、10 个文件，文字合计 ≤ 20 万字符。配文里 @机器人、用 /bug 或回复机器人都算反馈，相册与 3 秒内连发的多条合并成一条。Telegram 只允许机器人下载 20 MB 以内的文件；视频、语音、贴纸、动图不处理。没处理的附件会在同一条回复里说明。附件临时存在插件数据目录的 `attachments/`，这条反馈分诊结束（转交的在目标项目分诊结束）后删除，残留文件 24 小时后清理。
- 从内置版升级：第一次启动时自动导入旧的 `telegram.json`（token 转存到插件密钥），之后旧文件由 Fynvra 改名留底。旧的分诊 / 值班会话不归本插件所有，首次用到时会重建。

## 开发

源码在 `src/`（TypeScript），`dist/` 是提交到仓库的编译产物（ESM、未压缩、保留注释），`host.main` 指向 `dist/index.js`。运行时只用 Node 内置模块，没有 npm 依赖。

重新编译（借用 Fynvra 仓库自带的 TypeScript 与 `@types/node`，在注册表仓库根目录执行）：

```bash
node ../fynvra/node_modules/typescript/bin/tsc -p official/com.fynvra.telegram --typeRoots ../fynvra/node_modules/@types
```

改完源码要重新编译并一起提交 `dist/`；编译后 `git status` 应当没有 `dist/` 的额外改动。
